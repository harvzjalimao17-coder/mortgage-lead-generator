# G. IMPLEMENTATION RISKS

- **n8n webhook:** breaks only if step-navigation allows submit before all steps validate, sending incomplete/undefined values into `Validate Lead` (checks `name`, `email`, `address`, `service`).
- **Supabase:** breaks only if `estimated_property_value` is ever sent as a non-numeric range string instead of the transformed midpoint — `Prepare Lead` does `Number(propertyValue)`, which would produce `NaN`/null silently if skipped.
- **Google Sheets:** same numeric-field risk as Supabase; otherwise just appends whatever string values arrive, no additional risk.
- **Duplicate checking:** unaffected as long as `email` is read at final-submit time (not cached from an earlier step the user may have edited via Back).
- **Lead scoring:** `Calculate Lead Priority` keys off `desired_timeline` and `service` string values (lowercased) — the Step 5 "ASAP"→"Immediately" rename and Step 1 new `service` options must exactly match the strings that node's scoring map expects, or new options will silently score as 0.
- **AI/GHL integration:** not applicable — confirmed absent from this repo's flow; nothing to break.
- **Mobile UX:** risk only if new step/choice-card CSS isn't tested at the existing `900px`/`600px` breakpoints already used by `.form-card`, and if shared classes are renamed in a way that also affects the separate `.contact-card` (AI message form).
